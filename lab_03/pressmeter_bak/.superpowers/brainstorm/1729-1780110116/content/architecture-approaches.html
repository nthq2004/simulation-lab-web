架构方案对比

基于现有平台 + Three.js 混合渲染的数字孪生架构

方案 A: 分层架构 (推荐)

核心理念：渲染与数据分离，三层独立演化

┌─────────────────────────────────────────┐
│  🖥️ 表示层 (Presentation)               │
│  ┌──────────────┐  ┌──────────────────┐ │
│  │ 2D Konva     │  │ 3D Three.js      │ │
│  │ 系统原理图    │  │ 机舱空间布局     │ │
│  │ P&ID风格     │  │ 设备3D模型       │ │
│  └──────┬───────┘  └────────┬─────────┘ │
└─────────┼────────────────────┼───────────┘
          │  事件总线 (Event Bus) │
┌─────────▼────────────────────▼───────────┐
│  🧠 数字孪生层 (Digital Twin)             │
│  ├── 设备对象池 (Equipment Objects)       │
│  ├── 状态管理 (State Manager)             │
│  ├── 物理仿真 (Physics Engine) ← 复用现有 │
│  └── 通信接口 (Comm Interfaces) ← 复用    │
└───────────────────────────────────────────┘
          │
┌─────────▼─────────────────────────────────┐
│  📊 数据层 (Data)                         │
│   设备参数 / 传感器数据 / 历史记录        │
│   (保持现有数据模型)                      │
└───────────────────────────────────────────┘

优势

  • 现有 Konva 组件完全复用，零改动
  • 3D 独立模块，不影响现有功能
  • 事件总线解耦，2D↔3D 独立更新
  • 可增量开发（先做 3D 外壳再填内容）

劣势

  • 需要设计事件总线接口
  • 2D/3D 状态同步需要额外维护

方案 B: 统一设备对象模型

核心理念：每个设备 = 一个数字孪生对象，内置 2D 视图 + 3D 视图 + 物理模型

class EngineRoomEquipment {
  id, type, position
  // 双重渲染
  konvaView: Konva.Group   // 2D 原理图符号
  threeView: THREE.Mesh     // 3D 模型
  // 物理仿真（复用现有求解器）
  physicsModel: CircuitSolver | PneumaticSolver
  // 状态
  sensors: Map<string, number>
  state: { running, temp, pressure, ... }
}

优势

  • 设备概念直观，封装完整
  • 2D/3D 天然同步（同一对象）

劣势

  • 需改造现有 BaseComponent，影响面大
  • Three.js 集成耦合度高

方案 C: 插件式扩展

核心理念：核心平台不变，3D 作为独立插件运行，通过共享数据总线通信

┌─────────────────┐     ┌─────────────────┐
│  Konva 2D 平台   │     │  Three.js 3D     │
│  (现有系统)      │     │  (新增插件)      │
│  - 组件系统      │     │  - 机舱场景      │
│  - 求解器        │◄───►│  - 3D模型        │
│  - 流程引擎      │ 总线 │  - 漫游控制      │
└─────────────────┘     └─────────────────┘
         │                      │
         └────── SignalBridge ───┘
           (扩展自现有信号桥接)

优势

  • 对现有系统侵入最小
  • 可独立启动 2D 或 3D

劣势

  • 2D/3D 功能割裂，联动较弱
  • 共享数据总线的扩展性有限

我的推荐: 方案 A — 分层架构

理由: 完美复用现有 Konva 组件（200+ 已实现），3D 独立开发不阻塞现有功能，事件总线设计为后续扩展（AR/VR、数据回放等）预留空间。
